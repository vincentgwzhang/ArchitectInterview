# 01. 集中日志、结构化日志与关联 ID

## Structured Logging

每条 Log 使用稳定字段：timestamp、level、service、version、environment、traceId、businessId、event、errorCode。JSON 便于集中检索与规则化处理。

## Correlation

- Trace ID：一次分布式调用链。
- Request ID：入口请求。
- Business ID：跨多次请求/小时的 Order、Saga。
- Event ID/Causation ID：异步因果链。

HTTP、gRPC、Kafka 都需传播 Context，并防止外部 Client 伪造可信内部字段。

## Log Level

- ERROR：需要行动的失败。
- WARN：异常但系统处理。
- INFO：重要生命周期/业务事件。
- DEBUG/TRACE：诊断，生产受控。

大量无行动 Error 会产生噪音。只在最有上下文的 Boundary 记录一次异常。

## 安全

禁止 Token、Password、完整 PII 和 Payment Data。使用 Redaction、访问控制、Retention 和 Audit。Log 本身也是敏感数据资产。

## Central Platform

统一采集、Buffer、Index 和 Archive，Agent/Collector 故障不能阻塞业务。成本通过 Sampling、Level、Retention、冷热分层控制。

## 总结

集中日志的价值是跨服务重建事件。稳定 Schema、关联 ID、数据安全和合理 Signal-to-noise 比打印更多内容重要。
