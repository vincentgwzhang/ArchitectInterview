# 05. 幂等键、去重表与一致性校验

## 幂等键

由 Client 或上游生成，Scope 包含 Tenant、Operation 和 Resource。Server 保存 Key、Request Hash、State、Response 和 Expiry。

并发首次请求需要 Unique Constraint，只有一个执行者，其余读取原状态。Key 相同但 Payload 不同必须拒绝。

## Consumer 去重表

```text
processed_events(consumer, event_id, processed_at)
UNIQUE(consumer, event_id)
```

在与业务修改相同 Transaction 中插入。若业务数据库与去重表不同，仍有 Dual Write 问题。

## 自然幂等

使用业务唯一键、Upsert、状态机和 Version 常比永久 Event ID 表更高效。例如 `shipment(order_id)` Unique 防止重复创建。

## Retention

去重记录保留时间必须长于 Broker Redelivery/Replay Window。主动 Replay 历史数据时可能需要独立 Replay Namespace 或可重建逻辑。

## 一致性校验

异步系统必须对账：

- Count/Sum/Hash。
- Source 与 Projection 差异。
- 卡住状态年龄。
- Missing Event。
- Balance/Inventory Invariant。

Reconciliation Job 发现并可自动修复安全差异，其他进入人工 Queue。

## 总结

幂等处理实时重复，对账处理未预见偏差。两者共同构成最终一致性安全网。
