# 04. 如何设计可承受下游故障的服务调用链

## 减少 Critical Path

先删除不必要同步调用。通知、Analytics、索引等通过 Event 异步。对必须同步的依赖定义清晰 Deadline 和失败语义。

## 保护层

- Deadline/Timeout。
- 仅幂等 Transient Retry + Jitter。
- Circuit Breaker。
- Bulkhead/Concurrency Limit。
- Rate Limit/Load Shedding。
- Cache/Stale Fallback（业务允许时）。

## Dependency Budget

如果上游 SLO 为 800 ms，给各下游分配预算并传播剩余 Deadline。避免三层各自等待 30 秒。

## Failure Domain

不同下游使用独立 Pool。Optional Dependency 故障不应占满核心线程。关键和非关键请求分优先级。

## 数据与 UX

明确 Partial Response、Degraded Flag、Retryable Error 和 PENDING。Payment 等 Unknown Outcome 使用 Status Query，不展示假成功。

## 测试

故障注入 Slow、Timeout、5xx、Connection Reset 和 Partial Region Failure。验证 Queue、Retry Traffic、Recovery 和 SLO。

## 观测

每个 Dependency 的 Latency/Error/Circuit State/Retry/Pool Wait，以及端到端 Trace。

## 面试亮点

强调先减少调用链，再保护，而不是堆叠所有 Resilience Pattern。说明 Pattern 本身如何造成 Retry Storm。
