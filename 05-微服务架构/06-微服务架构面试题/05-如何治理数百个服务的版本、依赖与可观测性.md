# 05. 如何治理数百个服务的版本、依赖与可观测性

## Platform as Product

建立 Self-service Golden Path：Service Template、CI/CD、Identity、Secret、Telemetry、Deployment、SLO Dashboard 和 Catalog。Stream Team 在 Guardrail 内自治。

## Service Catalog

自动收集 Owner、Tier、API/Event、Dependency、SLO、Runbook、Version、Data Class 和 Lifecycle。无 Owner/Tier 的 Service 不得成为生产关键依赖。

## Contract

OpenAPI/AsyncAPI/Schema Registry、Compatibility Check、Consumer Contract、Deprecation/Sunset。Runtime Trace 补充静态 Dependency Map。

## Version

独立 Service 不要求统一版本。强调向后兼容、渐进部署和 Consumer Visibility。基础 Library 用自动 Upgrade PR，但避免组织级 Lockstep Release。

## Observability

OpenTelemetry 标准、统一 Semantic Attribute、RED/Golden Signal、Trace Sampling 和 SLO Burn-rate Alert。Dashboard 模板统一但 Ownership 分散。

## Governance

Policy as Code 检查 Security、Resource、Probe、Image 和 API。高风险例外有 Owner、补偿控制和 Expiry；架构团队不审批每个 Deployment。

## 衡量

Lead Time、Change Failure、MTTR、SLO、Vulnerability Age、Platform Adoption、Exception 和 Unit Cost。

## 面试亮点

治理核心是自动化平台、Metadata 与 Ownership，而非建立一个中央委员会管理数百个团队。
