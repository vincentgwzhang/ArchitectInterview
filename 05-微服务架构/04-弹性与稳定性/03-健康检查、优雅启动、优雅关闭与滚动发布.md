# 03. 健康检查、优雅启动、优雅关闭与滚动发布

## Health Probe

- Startup：应用是否完成慢启动。
- Liveness：进程是否无法自行恢复，需要重启。
- Readiness：当前是否可以接收流量。

Liveness 不应依赖共享 Database，否则数据库故障会重启所有 Pod。Readiness 也应谨慎，防止瞬时依赖问题导致全部实例被摘除。

## Graceful Start

加载配置、建立必要连接、Warm Cache/JIT 后才 Ready。Consumer 在完全初始化后再接收 Partition/Message。

## Graceful Shutdown

1. 标记 Not Ready，停止新流量。
2. 等待 Load Balancer 传播。
3. 完成或取消 In-flight Request。
4. 停止消费新消息，提交已完成 Offset。
5. Flush Telemetry。
6. 在 Grace Period 内退出。

Side Effect 任务需 Idempotent，以应对强制终止。

## Rolling Deployment

设置 MaxUnavailable/MaxSurge、Readiness 和足够 Capacity。新旧版本共存意味着 API、Event 和 Database Schema 必须向后兼容。

## PDB 与终止

PodDisruptionBudget 保护自愿中断，不能阻止 Node Crash。Termination Grace Period 必须覆盖真实请求/Job 时长，但不能无限大。

## 总结

健康检查和生命周期 Hook 决定部署是否真正零停机。必须在实例、LB、Consumer 和 Schema 层共同验证。
