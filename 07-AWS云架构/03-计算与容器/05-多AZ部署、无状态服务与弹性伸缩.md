# 05. 多 AZ 部署、无状态服务与弹性伸缩

## 无状态

Compute Instance 不保存不可转移 Session/File/Job 状态。Session 放 DynamoDB/Redis 或使用安全 Token，文件放 S3，工作状态放数据库/Queue。

无状态让负载均衡、替换、扩缩容和 AZ Failover 更简单，但状态存储本身需高可用。

## Multi-AZ

Load Balancer 和 ASG/ECS/EKS 跨 AZ，使用 Topology Spread。数据库使用 Multi-AZ/Replica。失去一个 AZ 后剩余实例与 NAT/Endpoint/连接必须承载 Peak。

## Auto Scaling

根据 Workload 选择 CPU、Request/Target、Queue Age、Concurrency 或 Custom Metric。设置 Warmup、Cooldown、Min/Max 和 Scheduled Scaling。

## 启动与关闭

启动完成 Warmup/JIT/Dependency 后 Ready；关闭先 Deregister，再完成 In-flight。短突发快于启动速度时需预留 Capacity 或 Queue。

## 下游保护

Application 扩容会增加 DB Connection 和 API 流量。使用 Pool Budget、Concurrency Limit、Rate Limit 和 Backpressure。

## 总结

弹性不是无限实例。无状态、多 AZ、正确 Scaling Signal、生命周期和下游容量共同决定真实可用性。
