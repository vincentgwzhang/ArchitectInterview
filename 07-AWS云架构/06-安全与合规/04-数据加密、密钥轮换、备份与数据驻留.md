# 04. 数据加密、密钥轮换、备份与数据驻留

## 加密

In transit 使用 TLS；At rest 使用服务集成的 KMS。按数据分类选择 AWS-owned、AWS-managed 或 Customer-managed Key。高敏感数据可按 Tenant/Domain 分 Key，但 Key 数和运营成本增加。

## Key Rotation

KMS 自动/手动轮换改变新加密材料，旧 Ciphertext 仍可解密。需要 Crypto-shredding 时理解删除等待期和 Blast Radius。Cross-region/Account Key 与 Backup 恢复要预先验证。

## Backup

使用 AWS Backup/服务 Snapshot，跨 Account/Region Copy、Vault Lock、Retention 和 Restore Test。Encryption Key 权限必须随 Backup 可恢复。

## 数据驻留

明确数据、Metadata、Log、Backup、Support Access 和 Subprocessor 可去哪里。限制 Region、SCP/Config 检测、部署 Pipeline Guardrail。Global Service 的控制面/数据面行为需逐项确认。

## 删除

Retention、Legal Hold、用户删除与 Backup 到期要协调。删除 Primary 不等于立即从所有 Backup 消失，应有 Policy 与可解释过程。

## 总结

数据保护涵盖加密、Key、Backup、Region 和生命周期。必须做 Restore 与权限演练，而不是只开启默认 Encryption。
