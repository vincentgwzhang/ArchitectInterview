# 05. 零信任、纵深防御与安全事件响应

## Zero Trust

不因网络位置自动信任。每次访问基于身份、设备/Workload、Context、Resource 和 Policy，使用短期 Credential、最小权限和持续验证。

## Defense in Depth

```text
Organization/SCP
-> Identity/MFA
-> Network/Endpoint/WAF
-> Application Authorization
-> Data Encryption/Classification
-> Detection/Audit/Response
```

任一层被绕过，其他层仍限制影响。

## Workload

EC2/ECS/EKS/Lambda 使用 Role，不存 Access Key；Service-to-service 使用 Identity 与 TLS；Security Group/Network Policy 最小路径。人员通过 Identity Center 和 Just-in-time Elevated Access。

## Incident Response

准备：Account/Role 隔离、Credential Revocation、Snapshot/Evidence、CloudTrail 查询、通信、Legal/Privacy 通知和恢复 Runbook。Security Account 保留独立响应权限。

## 自动响应

EventBridge + Lambda/SSM 可隔离 Instance、禁用 Key 或限制 Policy，但必须有 Severity、验证、Rollback 和 Audit，避免误报造成生产中断。

## 演练

Tabletop 与 Game Day 测 Credential Leak、Public Bucket、Ransomware、Root/Management Account 和 Log Pipeline 故障。

## 总结

Zero Trust 是持续授权原则，纵深防御限制 Blast Radius，Incident Response 把检测转化为可恢复行动。
