# 05. 如何在可靠性、性能、安全与成本之间权衡

## 建立 Driver

先量化 SLO、P99、RTO/RPO、Data Class、Budget、Deadline 与团队能力。没有目标，“最佳 AWS 架构”不存在。

## 典型权衡

- Multi-region 提高恢复能力，但增加复制冲突与成本。
- Cache/CDN 提升性能、降 Origin 成本，但增加 Staleness。
- Private Endpoint 降低公网/NAT 风险，但有小时费与 DNS 复杂度。
- Managed Service 提高交付/运营效率，但可能增加 Usage Cost/Lock-in。
- Strong Consistency 保护 Invariant，但提高跨 Region Latency/降低 Partition Availability。

## 分层

按 Service Tier 使用不同 Reliability/Security，而不是全部最高规格。关键交易 Multi-AZ + Warm DR；非关键报表可单 Region + Backup。

## 决策方法

比较方案的 Business Impact、TCO、Residual Risk、可逆性和演进 Trigger。用 Load Test、DR Drill、Threat Model 和 Cost Model 验证未知。

## Guardrail

Security/Compliance 最低线不可被普通成本优化突破。Cost 优化在 SLO 与风险边界内进行。

## 面试表达

明确“选择什么、为何、放弃什么、如何降低风险、何时重评”。用 ADR 保存假设和证据。

## 总结

架构师的价值不是选择最多服务，而是用最小必要复杂度满足业务质量目标，并保留可验证演进路径。
