# 03. 单元、集成、契约、E2E 与性能测试金字塔

## 测试层次

- Unit：Domain/函数，快且定位清楚。
- Component：Service + 真实 Framework，外部依赖可替代。
- Integration：Database、Kafka、Cloud Service 集成。
- Contract：Producer/Consumer 兼容。
- E2E：少量关键 User Journey。
- Performance/Resilience：容量与故障行为。

## Test Pyramid

底层数量多、反馈快；越高层数量越少、成本越高。现代系统也可用 Test Trophy 强调 Integration，但原则仍是把问题放在最低有效层验证。

## Test Container

用真实 PostgreSQL/Kafka Container 比内存替代品更接近生产。固定 Version、隔离数据，并控制启动 Cache。

## Contract

OpenAPI/Schema Compatibility 和 Consumer-driven Contract 防止独立服务变更破坏 Consumer。它不替代业务 E2E。

## E2E

覆盖 Login、Checkout、关键 Admin 等高价值路径。测试数据可重复、环境稳定、保存 Trace/Screenshot。治理 Flaky，不用 Sleep 猜等待。

## Performance

Baseline、Load、Stress、Spike、Soak 和 Failover。生产式数据/依赖/Cache，结果作为趋势与 Release Risk，而不是每个 PR 都跑最大压测。

## 总结

测试组合按风险提供最快反馈。多数逻辑低层验证，跨边界 Contract，中等 Integration，少量 E2E 和周期性性能/恢复测试。
