# 01. 设计支持数百个 Microservice 的交付平台

## 目标

Self-service、标准安全、独立发布、可观测、低认知负担。澄清团队数、Cloud/Cluster、合规、部署频率与 Multi-region。

## 平台架构

```text
Developer Portal -> Service Template/Catalog
Git -> CI Build/Test/Scan/Sign -> Artifact Registry
Config Repo -> GitOps Controller -> Clusters
Policy/Secret/Identity/Observability shared services
```

## Golden Path

模板预置 Java/React Build、OpenTelemetry、Health、Docker、Helm、SLO、Dashboard、Runbook 和 Ownership。允许 Escape Hatch，但例外有 Risk/Expiry。

## CI

共享 Versioned Component、Ephemeral Runner、Remote Cache、OIDC。Build Once，SBOM/Provenance/Signature 与 Artifact 一起发布。

## CD

GitOps 管期望状态，按 Environment Promote Digest。Canary/Blue-Green、自动分析和 Rollback。Database Migration 独立兼容流程。

## Multi-tenancy

Account/Namespace/Role/Quota/Network 隔离，Team 自助但无 Cluster-admin。Secret Manager 与 Workload Identity。

## 治理与指标

Service Catalog、API Schema、Policy as Code、DORA、SLO、Platform Adoption、Pipeline P95 和 Unit Cost。

## 面试亮点

把 Platform 当产品，有用户、SLO、Roadmap 和支持模型；避免一个中央团队手工部署数百服务。
