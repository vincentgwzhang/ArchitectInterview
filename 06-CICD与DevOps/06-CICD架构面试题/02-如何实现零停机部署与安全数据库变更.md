# 02. 如何实现零停机部署与安全数据库变更

## 应用前提

多 Replica 跨故障域、Readiness、Graceful Shutdown、足够 Surge Capacity。Load Balancer 停止新流量后等待 In-flight 完成。

## 兼容性

Rolling 时新旧版本共存：API/Event 向后兼容，Session 外置或兼容，Configuration 和 Feature Flag 可同时支持。

## Database

使用 Expand-and-Contract：加新结构 → 兼容代码 → Backfill → 切读写 → 观察 → 删除旧结构。大表 Online DDL/Concurrent Index，Batch Backfill 限速。

## 发布

Canary 小流量，比较 SLO/Error/Business Metric。异常停止扩流并 Rollback Code；Schema 通常 Roll-forward，旧 Code 必须能运行在 Expanded Schema。

## 长请求与消息

设置 Termination Grace；Consumer 停止取新消息、完成当前处理再 Commit。所有 Side Effect Idempotent，防强制终止重复。

## 验证

Synthetic Transaction、Version-specific Metric、DB Lock/Lag、Canary Analysis。Game Day 模拟 Pod Termination 和 Migration Failure。

## 面试亮点

“零停机”不只是 Deployment Strategy，还是 Lifecycle、Capacity、Contract 和数据库演进的联合属性。
