# 05. 如何设计跨账户、跨区域的发布和回滚流程

## 隔离

每环境/Region 独立 Account、Role 和 Resource。中央 CI 无长期 Key，通过 OIDC Assume Role，Trust 限制 Repository、Branch、Environment。

## Artifact

一次 Build/Sign，复制相同 Digest 到 Regional Registry。SBOM/Provenance 同步，部署只允许可信签名 Artifact。

## 配置与 IaC

Account/Foundation 使用 Versioned IaC；Application Config 通过 GitOps。Region 差异显式参数化，Secret 由各 Region Manager 提供。

## 发布顺序

1. Internal/Non-prod。
2. 一个低风险 Region/Cell Canary。
3. 自动验证 SLO/Business/Security。
4. 分 Wave 扩大，限制同时 Blast Radius。
5. Global Completion Check。

## 回滚

每个 Region 可独立停止/回滚。Global Controller 记录状态，不强迫已健康 Region 因单一区域问题全部回滚。数据库使用兼容 Schema 和 Roll-forward；流量可切回健康 Region。

## 故障

Control Plane/Region 不可用时，已有 Workload 继续运行；Pipeline 可暂停并保留状态。定义 Partial Success、Resume、Manual Override 和 Audit。

## 面试亮点

强调 Cell/Wave、短期身份、同一 Digest、区域自治回滚、数据兼容和 Control Plane 故障处理，而不只是并行执行多个 Job。
