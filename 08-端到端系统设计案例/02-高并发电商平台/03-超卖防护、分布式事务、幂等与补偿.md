# 03. 超卖防护、分布式事务、幂等与补偿

## 库存

用条件原子更新或 Reservation：`available >= quantity` 才扣减。热点 SKU 可按 SKU 串行分区/队列，但需容量与公平性。Cache 不作最终库存决定。

## 订单

Create Order 使用 Idempotency Key + Unique Constraint。相同 Key/不同 Payload 返回冲突。Timeout 后查询原 Operation。

## 支付

向 Provider 传 Idempotency Key；超时进入 `PAYMENT_PENDING`，通过查询/Webhook 确认，不盲目再次扣款。

## Saga

Inventory Reservation、Payment Authorization、Order Confirmation 各本地 Transaction。失败执行 Release/Refund；补偿也可失败，进入 Retry/DLQ/人工。

## 对账

周期比较 Order、Payment、Inventory 与 Fulfillment，发现 Missing Event、卡住状态和金额差异。最终一致性有收敛 SLO。

## 总结

防超卖和支付正确性来自数据库原子条件、幂等、显式状态、补偿与对账，而不是“Exactly once”口号。
