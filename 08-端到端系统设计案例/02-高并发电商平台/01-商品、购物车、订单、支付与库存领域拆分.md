# 01. 商品、购物车、订单、支付与库存领域拆分

## Bounded Context

- Catalog：商品描述与分类。
- Pricing/Promotion：价格规则。
- Cart：用户意向。
- Order：购买快照与生命周期。
- Inventory：可售量与 Reservation。
- Payment：授权、扣款、退款。
- Fulfillment：发货。

每个 Context 拥有数据，跨边界用 API/Event。不要按 Controller/Database 技术层拆服务。

## 一致性

Cart/Catalog 允许 Eventual；Checkout 重新验证 Price/Inventory；Order 保存商品和价格 Snapshot。Payment/Inventory 使用 Idempotency 与状态机。

## 流程

Order Saga：创建 Pending → Reserve Inventory → Authorize Payment → Confirm；失败 Release/Refund。Outbox 发布 Event。

## 团队

Stream-aligned Team 端到端拥有 Domain、SLO 和 On-call；Platform 提供交付、Identity、Telemetry 和 Messaging。

## 总结

服务边界围绕业务语言、不变量和 Ownership。交易流程跨 Context，但局部数据与规则保持内聚。
