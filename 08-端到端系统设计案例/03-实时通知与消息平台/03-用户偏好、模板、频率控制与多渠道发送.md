# 03. 用户偏好、模板、频率控制与多渠道发送

## Preference

按 Notification Type、Channel、Locale、Quiet Hours、Legal Consent 管理。Transactional Message 与 Marketing 的退订规则不同，合规优先。

## Template

版本化 Template、变量 Schema、Locale 和 Preview。变量默认转义，Email HTML Sanitize，禁止 Template 执行任意代码。发送记录保存 Template Version。

## Routing

Policy 决定 Push → SMS → Email 等优先级、Fallback 和用户设备。Fallback 只在业务允许且避免重复打扰。

## Frequency

Token Bucket/Sliding Window 按 User/Type/Channel 限频；Digest 合并低优先级通知；Quiet Hours 延迟。关键安全通知可绕过部分偏好，但需明确 Policy。

## Provider

Adapter 隔离供应商 API，统一 Error、Idempotency、Webhook 和 Status。Provider Health/Cost 决定 Route，但 Data Residency 与合规不能被自动回退破坏。

## 总结

通知平台核心是用户信任：偏好、同意、模板安全、频率和渠道状态比单纯发送吞吐更重要。
