# 04. 限流、降级、回退模型、语义缓存与故障隔离

## Rate Limiting 与 Quota

按 User、Tenant、Use Case、Model 和 Tool 限制：

- Requests/minute。
- Tokens/minute。
- Concurrent Request。
- Daily Cost。
- Agent Step/Tool Calls。

返回明确 Retry-After，并区分付费等级。Quota 是成本与公平控制，不只是防攻击。

## Load Shedding

过载时优先保护核心 Use Case：

- 拒绝低优先级 Batch。
- 限制 Output Length。
- 跳过非必要 Rerank。
- 降低 Agent Max Step。
- Queue 可延迟任务。
- 保留人工/关键交易能力。

## Fallback

回退到较小或另一 Provider Model 前验证：

- Output/Tool Compatibility。
- Quality 和 Safety。
- Data Residency。
- Context Limit。
- Cost。

无法安全回退时，宁可返回明确不可用，也不要静默产生低质量高风险结果。

## Semantic Cache

仅对可安全复用的场景启用。Key/Filter 包含 Tenant、ACL、Prompt/Knowledge/Policy Version、Locale 和 Time Sensitivity。设置相似度、TTL，并对答案引用重新验证。

## Bulkhead

按 Tenant/Use Case 隔离 Queue、Concurrency 和 Budget，防止一个大型 Agent Job 耗尽所有 Provider Quota。不同 Provider 使用独立 Circuit Breaker。

## Retry

只重试 Transient Error，使用 Exponential Backoff/Jitter 和总 Deadline。Streaming 已输出或 Tool 已有 Side Effect 时重试需特别处理。

## Degraded UX

向用户清楚说明：当前使用简化模式、无法访问实时数据或任务已排队。不要伪装完整成功。

## Chaos Test

模拟 Provider Timeout、Rate Limit、Vector DB Failure、Tool Slow、Cache Error 和 Region Outage，验证隔离、Fallback、Cancel 与 Recovery。

## 总结

AI Resilience 依赖多维限流、优先级、隔离和经过评测的降级。Fallback 必须保持安全与 Contract，而不只是“换一个 Model”。
