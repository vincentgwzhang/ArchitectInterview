# 05. 用户反馈、对话记录、追踪信息与分析平台

## 事件模型

一次 AI Request 应有稳定 Trace：

```text
conversation_id
request_id / parent_request_id
user/tenant pseudonymous scope
prompt/model/retrieval/tool version
token, latency, cost
citations and tool calls
policy decision
user feedback/outcome
```

不要依靠自由文本 Log 拼接完整链路。

## 对话记录

区分：

- 产品会话历史。
- Debug Trace。
- Audit Record。
- Evaluation Dataset。

它们有不同访问权限、Retention 和用途。不能默认把所有用户对话用于训练或评测。

## Feedback

显式：Thumb、Rating、Issue Category、用户编辑。  
隐式：Rephrase、Retry、Citation Click、Escalation、Task Completion、Abandonment。

提供具体原因选项比单一 Downvote 更可操作。反馈可能有偏且不完整，需要与抽样 Human Review 和客观 Task Metric 结合。

## Trace

Span 可覆盖 Gateway、Retrieval、Rerank、Model、Tool 和 Post-processing。记录输入输出时先做 Redaction，并允许只保存 Hash/摘要。

## Analytics

Dashboard 按 Use Case、Model、Prompt Version、Tenant Tier、Language 分析：

- Success/Acceptance。
- Safety/Refusal。
- Hallucination/Citation。
- Latency/Token/Cost。
- Tool Error。
- Retrieval No-hit。

控制高 Cardinality 与访问权限。

## 数据治理

- Consent 与 Purpose Limitation。
- PII Classification/Redaction。
- Encryption。
- Retention/Deletion。
- Data Residency。
- Role-based Access。
- Dataset Lineage。

用户删除请求需要传播到 Conversation Store、Analytics、Vector/Memory 和 Eval Dataset。

## 改进闭环

```text
Production signal -> Triage -> Label -> Eval set
-> Fix prompt/retrieval/model -> Offline eval -> Canary -> Monitor
```

## 总结

AI Analytics 必须连接版本、质量、成本和用户结果，同时隔离产品记录、审计与训练用途。可追溯和隐私治理同等重要。
