# 05. 审计日志、模型卡、数据血缘与责任边界

## 审计日志

高风险 AI 系统应记录：

- 谁发起请求，代表哪个 Tenant。
- 使用哪个 Model/Prompt/Policy Version。
- 检索了哪些 Source Version。
- 调用了哪些 Tool，参数与 Authorization Decision。
- 是否经过 Human Approval。
- 最终 Action/Outcome。
- Trace ID 和时间。

敏感 Prompt/Response 不一定全文保存，可使用 Redaction、Hash、受限 Vault 和分层 Retention。

## Model Card

Model Card 描述：

- Model/Version 与 Provider。
- Intended Use / Out-of-scope。
- Training/Data 已知信息。
- Eval Metric 和 Dataset。
- Limitation 与风险。
- Language/Domain Coverage。
- Safety Control。
- Deployment/Monitoring Requirement。

对第三方闭源 Model，记录供应商提供信息和自己的 Application-level Eval。

## System Card

实际风险来自完整系统，不只 Model。System Card 还应覆盖 RAG、Tool、Memory、Guardrail、Human Oversight、用户体验和 Failure Mode。

## Data Lineage

追踪：

```text
Source -> Parse/Chunk -> Embedding/Index -> Retrieval
       -> Prompt/Output -> Feedback -> Eval/Training Dataset
```

每步记录版本、Owner、Purpose、Permission 和 Retention。这样才能处理错误 Source、删除请求、License 和质量回归。

## 责任边界

明确 RACI：

- Product Owner：业务用途和用户影响。
- Model/AI Team：评测、Prompt、Routing。
- Data Owner：数据合法性、质量和访问。
- Platform：Runtime、Security、Reliability。
- Human Approver：高风险 Decision。
- Vendor：Contract 中承诺的服务与数据责任。

“AI 做了决定”不是责任主体。

## 变更管理

Model、Prompt、Retriever、Dataset、Policy 和 Tool 任一变化都可能影响行为。记录 Change、Eval、Approver、Rollout 和 Rollback。

## 总结

审计回答发生了什么，Model/System Card 说明适用边界，Lineage 说明数据如何流动，RACI 说明谁负责。四者共同形成可治理证据链。
