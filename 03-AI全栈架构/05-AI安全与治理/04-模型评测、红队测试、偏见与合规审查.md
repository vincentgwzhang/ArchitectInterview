# 04. 模型评测、红队测试、偏见与合规审查

## 风险评估

先按 Use Case 评估错误影响、用户群体、自动化程度、敏感数据和可逆性。客服草稿与自动贷款决定不能使用相同治理强度。

## 评测维度

- Task Quality。
- Robustness。
- Safety。
- Privacy。
- Fairness/Bias。
- Explainability/Citation。
- Security。
- Latency/Cost。

Dataset 应覆盖正常、边界、少数群体、恶意输入和历史生产失败。

## Red Team

模拟攻击：

- Prompt Injection/Jailbreak。
- Sensitive Data Exfiltration。
- Tool Abuse。
- Cross-tenant Access。
- Harmful Content。
- Social Engineering。
- Encoding/Multilingual Bypass。
- Long Context Attack。

记录 Attack Goal、Method、Success、Severity、Mitigation 和 Retest。Red Team 是持续过程，不是上线前一次活动。

## Bias/Fairness

明确 Protected/Relevant Group 和业务 Harm。按 Group 比较 Error Rate、False Positive/Negative、Allocation 或体验差异。

数据中缺少群体标签时需要谨慎设计评估，不能为了测 Fairness 反而不必要地收集敏感属性。与 Legal、Ethics、Domain Expert 协作。

## 合规审查

保留：

- Use Case 与 Intended Use。
- Data Source/License/Consent。
- Model/Provider 信息。
- Risk Assessment。
- Eval Evidence。
- Human Oversight。
- Logging/Retention。
- Incident/Appeal Process。

具体法规随地区和时间变化，应由专业团队确认，架构师负责把控制落到系统中。

## Release Gate

高风险 Change 需要 Safety Regression、Red-team Retest、Data Review、Owner Sign-off、Canary 和 Kill Switch。

## 总结

Responsible AI 需要场景化风险、代表性评测、攻击验证、公平性分析和可审计证据。治理必须贯穿整个 Model/Application Lifecycle。
