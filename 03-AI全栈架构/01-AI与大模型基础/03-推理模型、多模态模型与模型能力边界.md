# 03. 推理模型、多模态模型与模型能力边界

## 模型类型

- General-purpose Model：对话、总结、生成、简单推理。
- Reasoning Model：在复杂规划、数学、代码和多步任务上投入更多推理计算。
- Multimodal Model：处理文本、图片、音频或视频。
- Small/Specialized Model：低延迟、低成本的分类、抽取或边缘任务。

## 推理模型

推理模型通常在难题上更可靠，但可能更慢、更贵。适合：

- 多约束规划。
- 复杂代码与 Debug。
- 高价值分析。
- 需要 Tool 多步调用的任务。

简单分类和模板总结不应默认使用最强 Model。Model Routing 可以按任务复杂度升级。

## 多模态

常见场景：

- OCR 与文档理解。
- 图片问答和缺陷检测。
- 音频转录与客服分析。
- UI Screenshot 解析。

需要考虑 Media Size、Resolution、Sampling、隐私、存储、Copyright 和传输成本。模型“看见”图片不等于精确视觉测量，坐标、计数和小文本仍可能出错。

## 能力边界

LLM 是概率模型，典型限制：

- Hallucination。
- Knowledge Cutoff 或数据过时。
- 对长 Context 的利用不稳定。
- Prompt 表述敏感。
- 数值和精确逻辑可能出错。
- 不能自行获得未提供的权限与实时事实。
- 输出置信语气不代表真实置信度。

## 风险分层

按错误影响设计自动化等级：

- 低风险：文案草稿，可直接生成并由用户判断。
- 中风险：企业知识回答，需要 Citation 和 Feedback。
- 高风险：财务、医疗、权限变更，需要 Tool Verification、Rule Engine 和 Human Approval。

## Model Routing

基于任务、Language、Latency、Data Sensitivity、Cost 和 Quality 路由。设计 Fallback 时需注意不同 Model 的 Tool Schema、Output Format 和行为不完全兼容。

## 评估

不要用几个 Prompt 主观判断。建立代表性 Dataset，测 Task Success、Factuality、Safety、Latency、Token 和 Cost，并按场景分段。

## 总结

模型选择不是排行榜选择。理解任务风险和模型边界，使用 Routing、Tool、Validation 与 Human Oversight，才能把能力放在正确位置。
