# 01 Transformer、Token、Embedding 与 Attention 基础

本章连接两个层次：模型怎样把离散文本变成可计算表示，以及这些机制怎样影响 RAG、延迟、显存、成本和安全。RAG（Retrieval-Augmented Generation，检索增强生成）是先检索资料再把资料提供给生成模型的系统，不会自动把模型变成可靠数据库。

本文以常见稠密、因果 Decoder Transformer 为主，区分原始 Transformer 与后续变体。技术资料于 2026-11-27 核验，不给特定商业模型编造结构、价格或吞吐。算例为教学推演；未调用模型 API、运行训练或 GPU benchmark。

## 一、Token：模型处理的离散单位

### 1.1 从文本到 ID，再到文本

Tokenizer（分词器）将文本按自己的规则切成 Token 并映射为词表 ID。Token 可以是子词、字符、字节片段或符号组合，不一定是完整单词；特殊 Token 还可表示消息边界或控制结构。Token ID 是离散索引，本身的数值大小不表达语义远近。

常见方法包括 BPE（Byte Pair Encoding，逐步合并常见片段）和 Unigram 类方法；实际模型还有规范化、字节回退和特殊符号等细节。相同字符串在不同词表、版本或聊天模板下可能得到不同长度。空格、标点、代码缩进、Unicode 组合和语言都会影响切分，不能固定用“一个汉字一个 Token”换算。

模型生成 ID 后经解码得到文本，流式输出块未必对应一个完整词或用户可见字符。系统处理流式内容应按提供者协议拼接，不能假设每块都可独立解析成 JSON 或完整 UTF-8 文本。需要精确预算时使用与目标模型兼容的本地 tokenizer 或可靠计数方法，并计入消息模板；不能把一种模型的计数器当通用标准。

### 1.2 Token 与窗口、时延和成本

Context Window 是一次推理可用序列的容量约束，不是任意持久记忆。系统指令、历史、工具描述、检索内容和输出预留都消耗预算；不同服务对输入/输出上限及内部计数规则不同，必须查目标接口契约。

虚构预算：窗口容量 32,000，计划输入 20,000、最大输出 4,000，剩余 8,000 用于模板、工具结果及安全余量。若工具返回又增加 10,000，就不能只看最初用户问题很短而继续无界追加。可按优先级压缩历史、减少重复检索、截断非关键结果或拒绝超预算请求；必须保留任务约束和必要证据。

Token 影响 API 费用、吞吐和输出上限，但“Token 就是所有模型的唯一计费单位”过于绝对，图像、音频、缓存及不同服务可能另有规则。自托管成本还包括模型权重、显存、调度、空闲容量和运维。长度预算应和任务质量一起优化，不为省几个 Token 删除关键授权或事实条件。

## 二、Embedding：离散符号与检索语义空间

### 2.1 Token Embedding 不等于文档检索向量

Token Embedding 通常从可训练矩阵中按 ID 取出一个向量，给离散符号提供连续表示。经过 Transformer 后，同一个 Token 在不同上下文中的隐藏表示可能不同；输入查表向量与上下文化结果不能混为一谈。

句子/文档 Embedding 模型把一段内容编码为适合某任务的向量，可能通过池化等方式聚合，并用特定训练目标优化检索。不能随意取生成式 LLM 某一层平均值，就假设具有成熟检索模型同等能力。维度更高也不必然更准确，它增加索引和计算成本，效果取决于训练、领域与数据。

“语义相近通常距离近”是模型目标下的统计性质，不是客观真理。否定句、日期、数字差一个字符和专业缩写都可能被映射得很近；相关文档也未必回答当前问题。需要用真实业务评测集验证召回、排序与最终答案。

### 2.2 三种相似度及归一化

对于向量 x、y，点积为各维乘积求和；余弦相似度用点积除以两向量长度，强调方向；欧氏距离计算两向量差的长度，越小越近。

```text
dot(x,y) = Σ xᵢyᵢ
cos(x,y) = dot(x,y) / (||x|| ||y||)
distance(x,y) = sqrt(Σ (xᵢ-yᵢ)²)
```

点积同时受长度影响，余弦去除长度；零向量余弦无定义，应拒绝或处理。若两向量均归一化为单位长度，则平方欧氏距离等于 2−2×点积，三者的理想精确排序可对应；未归一化时不能这样假设。

模型要求的度量、输出是否已归一化，以及数据库“分数越大越好还是越小越好”必须一致。近似最近邻 ANN 为速度牺牲部分精确召回，还需调索引参数与过滤行为。不能拿不同模型的余弦阈值直接复用。

### 2.3 检索、聚类、推荐与语义缓存的边界

Retrieval 用向量找候选；Clustering 按空间结构分组；Recommendation 依据用户/内容表示找相关项；Semantic Cache 复用语义近似请求的结果。各自都需定义误匹配损失，不能“一套向量所有业务通吃”。

例如“订单 A 是否退款”和“订单 B 是否退款”可能语义非常接近，但结果不应共享。语义缓存键还需身份、租户、数据版本、参数与时效；高风险实时业务可不用语义缓存。权限过滤由服务端可信身份执行，不能让模型从用户提问中猜租户。

精确 ID、日期、数值和罕见术语常适合关键词/结构化查询。Hybrid Search 将语义与词法召回结合，再重排（Rerank）候选；重排提高相关性也有延迟成本，不代替授权。若向量数据库只在取 Top K 后过滤，候选可能被全部删掉导致漏召回，需理解预过滤/后过滤策略并测试。

## 三、Attention：按内容关联位置的计算

### 3.1 Q、K、V 从哪里来

Attention 是对可见位置的 Value 向量按权重加权。Self-attention 的 Query、Key、Value 通常来自同一序列隐藏表示的不同可训练投影，不是用户问题、数据库键和原文三份字面数据。Q 可理解为当前位置要找什么，K 是位置提供的匹配特征，V 是被汇聚的信息；这些只是解释计算的类比。

设输入 X 有 n 个位置、每个 d_model 维；单头投影产生 Q、K 的维度为 n×d_k，V 为 n×d_v。计算 QKᵀ 得 n×n 分数矩阵，每一行表示某个位置对所有位置的匹配。

```text
Attention(Q,K,V) = softmax(QKᵀ / sqrt(d_k) + M) V
```

M 是掩码：允许位置通常加 0，不允许位置加负无穷的概念值，使 softmax 权重为零。softmax 按每行把分数转换为非负、和为 1 的权重。除以 sqrt(d_k) 用来控制点积分数随维度增大的尺度，避免分布过尖导致训练困难，不是为了“把运算复杂度开平方”。

若某行分数是 [0,0]，权重为 [0.5,0.5]；对应 V 为 [2,0] 和 [0,4]，结果为 [1,2]。这是信息混合，不是从原文只拷贝一个词，也不是相似度最高处必然被完整采用。

### 3.2 因果掩码、多头与位置

生成式 Decoder 用因果掩码（Causal Mask）使位置只能看自身及之前的 Token，避免训练时偷看未来答案。Encoder 常可双向看整个输入；Cross-attention 的 Q 与 K/V 来自不同序列，例如原始翻译模型 Decoder 关注 Encoder 输出。不能把所有 Attention 都称为双向或因果。

Multi-head Attention 用多组投影计算后拼接并投影，让模型具有多种关联表示能力。但不能保证某个头永远代表语法、另一个永远代表事实，也不能仅靠注意力热图证明模型推理理由。

只有内容关联而没有位置信息，模型难以表达顺序差异。原始 Transformer 使用位置编码；其他模型可用学习位置、相对位置或 RoPE 等方式。RoPE 在 Q/K 中引入与位置相关的旋转，帮助表示位置关系；具体长度外推仍取决于训练与实现，不是任意扩大配置就能可靠延长上下文。

## 四、Transformer：Attention 不是全部

Transformer 层通常包含 Attention、逐位置 Feed-forward Network（前馈网络）、残差连接和归一化。Attention 负责跨位置汇聚，FFN 对每个位置做非线性变换，残差让信息和梯度有直接路径，Normalization 稳定数值与训练。现代模型可能使用不同归一化顺序、激活和门控结构，不能把原论文细节当所有模型保证。

原始 Transformer 是 Encoder–Decoder 翻译结构；常见生成式 LLM 使用 Decoder-style 自回归建模。最终隐藏表示映射到词表 logits，再形成下一个 Token 的概率分布。选择最高概率或按采样策略取 Token，追加回上下文并继续，直到终止条件或输出预算。

训练常用已知序列并行计算各位置的“下一个 Token”损失，因果掩码阻止泄漏；普通自回归推理则要先生成前一个结果才能确定后续输入。因此“训练可并行”不等于“一次普通前向就生成任意完整回答”。批处理可并行多个请求，但每个请求仍有依赖链。

模型优化的是训练目标，不是显式事实验证。流畅、高概率文本仍可能错误；参数不等于实时数据库，Embedding 相似不等于证据充分。架构中要明确检索来源、时间、引用和校验，敏感执行交由确定性权限与业务规则。

## 五、Prefill、Decode 与 KV Cache

### 5.1 两个推理阶段的瓶颈不同

Prefill 处理整个输入前缀并建立各层表示与缓存；长 Prompt 通常增加计算、显存与首 Token 等待。Decode 每步基于已有前缀生成新 Token，长输出累积逐步时延。首 Token 延迟 TTFT 还包括排队、网络、检索和预处理，不能全部归为模型计算。

TPOT 是输出 Token 间的平均时间等解码指标，端到端时间还需加 Prefill 与外部工作。流式可以让用户早看到内容，不减少生成相同输出必需的全部工作。吞吐是单位时间处理量，单请求快和总吞吐高不一定同时最优，批处理提高硬件利用也可能增加排队。

标准全 Attention 的输入阶段关联计算随序列长度呈平方项增长；模型 FFN、投影等还有其他成本。高效 Attention 内核可减少中间矩阵物化和内存访问，但不能一概宣称所有长序列成本线性。局部/稀疏 Attention 等改变算法，需按目标模型分析。

### 5.2 为什么缓存 K/V

对因果 Decoder，过去位置在前缀不变时不受未来 Token 影响，因此各层旧 K、V 可以复用。新一步仅计算新位置并关注旧 K/V，避免每步完整重算前缀。通常不需要同样缓存所有旧 Q，因为下一步要用的是新 Query；这不是把完整回答缓存起来。

KV Cache 仍需存储和读取不断增长的历史；有缓存并不意味着 Decode 与上下文长度无关。前缀修改会使相关缓存失效，不能换系统指令或检索内容后继续无条件复用；跨用户缓存还要隔离和保护隐私。缓存是中间状态，不会更新模型权重。

近似容量公式：

```text
KV bytes ≈ 2 × L × B × T × H_kv × d_head × bytes_per_element
```

L 为层数，B 为同时保留序列数，T 为每序列长度，H_kv 为 KV 头数，d_head 为头维度，2 表示 K 与 V。真实部署还有分页、碎片、元数据、不同长度、并行切分与量化开销。

虚构例：32 层、1 序列、8192 Token、8 个 KV 头、头维 128、每元素 2 字节，约为 1 GiB；32 个同长度序列约 32 GiB，仅算 KV，不含权重与其他内存。可见窗口和并发会直接争用容量，不能只看参数大小判断一张卡能承载多少会话。

### 5.3 MHA、MQA、GQA 的取舍

MHA 通常每个 Query 头有对应 K/V 头；MQA 让多个 Query 头共享一组 K/V；GQA 则按组共享，在头数之间折中。这可降低 KV 容量和读取带宽，但属于模型结构及训练选择，不是服务端随手改配置而保持原质量的免费优化。

KV 量化、分页管理、前缀缓存等可改善容量利用，各有精度、实现、隔离和命中条件。本文不提供通用加速倍数，实际效果需在具体模型、硬件、序列和并发分布上评估。

## 六、把基础机制落实到 RAG 与系统设计

### 6.1 Chunk、索引版本与上下文预算

Chunk 是索引时的文本片段。太小易丢上下文，太大让向量语义混杂并增加生成输入；重叠可保留边界，但会重复存储和召回。分块按标题、段落、代码或业务结构，保留文档 ID、片段位置、版本、时间和权限元数据，再用问题集评估。

换 Embedding 模型即使维度相同也可能改变空间含义，旧文档向量不能随意和新查询向量混检。模型、归一化、指令前缀、分块与预处理都应版本化。变更后构建新索引、回填并比较，再原子切换；删除/权限变更还要清理缓存和旧索引，避免“下线”内容继续可见。

上下文大不代表能等效利用每个位置。Lost in the Middle 在其测试模型和任务中发现位置敏感性，不能推成所有后续模型固定规律；系统仍应评估相关证据在前、中、后、多个片段和噪声下的表现。先召回正确资料、去重重排，再给足必要上下文，比把所有文档塞满窗口更可控。

### 6.2 权限、精确事实和失败处理

权限在检索前/检索中按可信租户与访问控制过滤，并在最终交付前按需要复核；不能指望向量距离排除别人文档。检索文本属于不可信数据，可能包含诱导模型忽略规则的提示注入，应隔离数据与指令，并用工具权限白名单限制执行。

日期、ID、数值查询可先结构化过滤或精确检索，再用语义检索补解释。没有足够证据就说明无法确认或请求补充，不因模型能生成句子就返回伪确定答案。向量检索失败、索引落后或无权限都需要不同诊断，不能统一改成“知识库没有内容”。

语义缓存还要包括模型/Prompt/数据版本、身份和新鲜度；会话 KV、检索结果缓存、最终回答缓存是不同层，失效条件不能混用。跨层重试会放大成本，设置总超时、取消和预算，避免一次失败触发无界生成。

### 6.3 排障和成本优化顺序

| 现象 | 优先观察 | 可能措施与边界 |
| --- | --- | --- |
| 首 Token 慢 | 排队、检索、输入长度、Prefill | 减少重复上下文、控制并发、缓存合法前缀 |
| 输出很慢 | 输出长度、Decode、KV 带宽 | 限制不必要输出，选择合适模型，验证吞吐与质量 |
| 显存不足 | 权重、并发、序列、KV 与碎片 | 长度准入、批调度、量化/分页；不可只盲加窗口 |
| 相似内容找不到 | 模型语言、分块、度量、过滤和 ANN | 用标注集分解召回与排序问题 |
| 回答引用错版本 | 文档版本、索引事件和缓存 | 版本化重建、失效与审计，不只调 Prompt |

质量指标看 Recall@K（前 K 候选中找回相关证据的能力）、排序、答案忠实性与任务成功；性能看 TTFT、输出速率、端到端分位数及并发；成本看每成功任务而不只每 Token 单价。优化某阶段可能把负担转到另一阶段，例如重排减少输入但增加检索时延，必须测完整链路。

## 七、面试完整回答与深入追问

**问：用几句话连接 Token、Embedding、Attention 和 Transformer。**

答：Tokenizer 把文本转成离散 ID，Token Embedding 提供连续输入表示；Attention 通过 Q/K 匹配对可见 V 加权，结合位置信息建立上下文关联；Transformer 将 Attention、前馈、残差和归一化堆叠，生成模型再输出下一个 Token 的分布。检索 Embedding 是另一个经过任务优化的向量接口，不等于随便取生成模型内部状态。

追问“Attention 是否等于理解？”答：它是可学习的信息汇聚机制，不直接保证事实、因果推理或权限，系统仍需证据与确定性控制。

**问：为什么中文字符数不能估 API Token？**

答：切分依词表和规则，中文、代码、空格与 Unicode 的片段长度不同，模板与工具内容也占预算。应按目标 tokenizer 计数并预留输出，不能固定字符比例；费用还要看服务具体规则。

追问“改模型只换名字吗？”答：还需核对 tokenizer、窗口、接口和输出行为，重新评测质量、性能与预算，不能复用所有旧假设。

**问：KV Cache 解决什么，又带来什么？**

答：复用因果前缀各层 K/V，避免每步重算历史，但存储随层数、长度、KV 头和并发增长，解码仍要读历史。更长上下文会压缩可承载并发，缓存也需隔离与失效。

追问“为什么不是缓存 Q？”答：新一步主要用新 Query 关注历史 K/V，不需要重新输出旧位置的结果，所以缓存历史 Q 没有同样必要。

**问：Embedding 相似为何不替代授权？**

答：相似度只表达训练空间的相关性，不包含当前用户权限的可信判定。其他租户相同问题可能距离最近，必须由服务端按租户和 ACL 过滤，缓存也同样隔离。

追问“过滤后没有结果怎么办？”答：区分无权限、过滤过严及召回不足，不能自动放宽授权；改检索策略或明确无法确认。

**问：窗口越大 RAG 越好吗？**

答：不必然，更多材料增加延迟、成本和噪声，模型对位置与任务的有效使用也有限。按证据召回、重排、去重及预算选择内容，用长上下文评测而非宣传上限决定。

追问“换 Embedding 为什么要重建？”答：空间和分块语义可能改变，即使维度相同也不兼容；需版本化索引并切换，避免新旧向量混用。

## 八、扫雷自测与速记

1. **Token ID 差值能代表语义差吗？** 不能，ID 是词表索引，语义来自学习表示。
2. **Token Embedding 与检索向量一样吗？** 不一样，输入查表和面向句段检索的表示有不同训练与使用契约。
3. **余弦与点积永远同排序吗？** 不，长度影响点积；单位归一化后才有相应关系，且索引近似还会影响召回。
4. **Attention 只取最高分位置吗？** 通常是 softmax 后加权组合，不是硬选一个词。
5. **因果训练为什么能并行？** 已知完整训练序列，各位置用掩码限制可见范围；推理时未知下一 Token，依赖链仍存在。
6. **有 KV 后长窗口不费资源吗？** 仍费，容量和历史读取随长度及并发增长，未缓存的计算也存在。
7. **8K 窗口改成 128K 配置一定可靠么？** 不保证，位置处理、训练分布、显存与质量都需验证。
8. **高相似度能保证数值答案正确吗？** 不能，近似数字和否定可能很近，需结构化核验与证据。
9. **同维 Embedding 可以混索引吗？** 不应默认可以，不同空间坐标无统一语义，需明确兼容证据。
10. **流式输出意味着总生成工作减少吗？** 不意味着，只是更早展示部分结果，总成本还取决于实际执行与输出长度。

速记：Token 决定序列预算；Embedding 定义表示空间；Attention 做受掩码约束的信息混合；Transformer 组合层与预测目标；Prefill 看输入，Decode 看依赖链；KV 换计算为容量与带宽；RAG 还需权限、精确检索、版本与评测。
