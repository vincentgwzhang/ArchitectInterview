# 05. 如何评估并持续改进一个生成式 AI 产品

## 从用户目标开始

先定义用户要完成什么，而不是只测回答“看起来不错”。北极星指标可以是 Ticket Resolution、Research Time Saved、Draft Acceptance 或 Conversion。

## 指标体系

### Product

Task Completion、Adoption、Retention、Escalation、Time Saved。

### Quality

Correctness、Groundedness、Completeness、Citation、Tool Success、Refusal Quality。

### Safety

Policy Violation、Data Leakage、Unauthorized Tool、Bias/Harm。

### System

P95 Latency、Availability、Error、Token、Cost per Success。

## Dataset

建立 Golden、Challenge、Safety 和 Fresh Production Sample，按 Language、Tenant、Difficulty 和 Use Case 分层。每个生产重大失败在清洗后加入 Regression Set。

## 改进循环

```text
Observe production
-> Triage failure: retrieval/model/prompt/tool/UX
-> Add labeled example
-> Change one component
-> Offline eval
-> Red-team/safety regression
-> Shadow/Canary/A-B
-> Monitor and rollback if needed
```

## Failure Taxonomy

区分：No Retrieval、Wrong Retrieval、Unsupported Claim、Tool Selection、Argument、Policy、UX、Latency。否则团队会把所有问题都归因于“换更强 Model”。

## Human Review

Domain Expert 使用明确 Rubric 盲评。校准 Reviewer 并抽查一致性。LLM Judge 用于规模化，但以 Human-labeled Set 检查偏差。

## Experiment

A/B Test 使用稳定 Conversation 分桶，预先定义 Primary/Guardrail Metric。高风险变更先 Shadow 和人工验证。

## Governance

每个 Use Case 有 Owner、Model/System Card、Release Manifest、Risk Tier、Kill Switch 和 Review Cadence。用户 Feedback 提供纠正与申诉渠道。

## 面试亮点

强调产品 Outcome、分层诊断、人机结合评测、生产反馈与安全门禁，而不是只说 Prompt Engineering。

## 总结

生成式 AI 改进是持续的产品与工程系统。可靠进步来自可重现评测、失败分类、受控实验、生产信号和明确责任。
