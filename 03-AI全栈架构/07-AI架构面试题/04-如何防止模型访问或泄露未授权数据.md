# 04. 如何防止模型访问或泄露未授权数据

## 原则

模型不能成为权限判断者。Security Boundary 必须在 Identity、Retrieval、Tool Runtime、Cache 和 Output Pipeline 中强制执行。

## Identity

从可信 Session/OIDC Token 获取 User、Tenant、Group 和 Delegated Scope。不要接受 Prompt 中声明的“我是管理员”。

## Retrieval

Document/Chunk 带 ACL Metadata，在 Query 时 Pre-filter。Vector、Keyword、Rerank 和 Parent Fetch 全链路都保持 Scope。建立自动 Cross-tenant Canary Test。

## Tool

Tool Runtime 重新检查 Resource-level Authorization。使用 On-behalf-of User 或显式 Policy Decision，避免一个高权限 Service Account 让 Agent 访问所有数据。

## Cache

Key 包含 Tenant、User/Group Scope、Knowledge Version 和 Policy Version。敏感结果使用 Private Cache 或不缓存。语义相似不能跨权限复用。

## Context 与输出

- Data Minimization。
- PII/Secret Redaction。
- Provider Data Policy 与 Region。
- DLP Output Scan。
- Citation 再授权。
- Log/Trace 默认不保存明文。

## Prompt Injection

外部文档是 Data，不提升其指令优先级。限制 Tool，审批高风险动作。即使模型被成功操纵，权限层仍应阻止访问。

## 删除与生命周期

删除传播到 Source、Index、Cache、Memory、Conversation、Analytics 和 Eval Dataset。保留 Lineage 证明数据去了哪里。

## Detection

Audit Access、异常跨 Tenant Query、DLP Alert、Honeytoken 和 Red-team。准备撤销 Credential、关闭 Tool/Source 和通知 Data Owner 的 Incident Runbook。

## 面试亮点

说明 Defense in Depth：Model Alignment 只是软层，真正保证来自检索前 ACL、Tool Authorization、Tenant-aware Cache、最小数据和审计测试。
