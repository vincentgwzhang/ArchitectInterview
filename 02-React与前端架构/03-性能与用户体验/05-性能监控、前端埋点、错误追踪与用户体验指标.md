# 05. 性能监控、前端埋点、错误追踪与用户体验指标

## 前端 Observability

Frontend 是真实用户、Browser、Network、CDN 和 Backend 的交汇点。需要关联：

- RUM Performance。
- JavaScript Error。
- Network/API Error。
- User Journey Event。
- Release Version 与 Source Map。
- Backend Trace。

## RUM

采集 Core Web Vitals、Navigation Timing、Resource Timing 和 Long Task，并按 Route、Device、Browser、Region、Network、Version 分段。

使用 Sampling 控制成本，避免采集输入内容、Token 和 PII。

## 错误追踪

错误事件至少包含：

- Error Type/Message/Stack。
- Source Map 后的源码位置。
- Release Version。
- Route 和 Component Stack。
- Trace/Correlation ID。
- Breadcrumb。
- 受影响 Session 数。

按 Fingerprint 聚合，避免同一错误产生海量 Issue。Source Map 应安全上传到错误平台，而不一定公开部署。

## 埋点设计

优先记录 Domain Event：

```text
checkout_started
payment_submitted
order_confirmed
checkout_failed
```

统一 Event Schema、Owner、Version 和 Data Classification。不要每个团队随意发 `button_clicked_2`。

## 用户体验指标

技术指标与业务指标关联：

- LCP 与 Bounce Rate。
- INP 与 Task Completion。
- API Error 与 Checkout Conversion。
- Crash-free Session。
- Rage Click、Dead Click。
- Funnel Drop-off。

相关性不等于因果，需要 A/B Test 或控制变量验证改进。

## Trace Correlation

Frontend 为请求发送 Trace Context，Backend 返回可关联 ID。这样可从用户失败 Session 跳转到 API Trace，而不在 UI 暴露内部敏感信息。

## 告警

对 Release Regression、Crash-free Session、关键 Funnel Failure 和 Core Web Vitals 设置聚合告警。单个用户网络失败通常不应 Page On-call。

## 数据治理

- Consent 管理。
- Data Minimization。
- Retention。
- User Deletion。
- Access Control。
- Sampling 和 Masking。

## 总结

前端监控要把技术信号连接到真实 User Journey，并能从 Version、Browser 和 Trace 定位根因，同时遵守隐私和成本边界。
