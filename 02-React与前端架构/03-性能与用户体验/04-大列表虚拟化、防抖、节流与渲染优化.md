# 04. 大列表虚拟化、防抖、节流与渲染优化

## 列表虚拟化

Virtualization 只渲染 Viewport 附近的 Row，把几万条数据的 DOM Node 控制在较小数量。

需要处理：

- 固定或动态 Row Height。
- Overscan。
- Scroll Position 恢复。
- Keyboard Navigation 和 Screen Reader。
- Sticky Header。
- Infinite Loading。

虚拟化降低 DOM/Render Cost，但不会减少 Backend 数据量，应配合 Pagination 或 Cursor。

## Debounce

用户停止输入一段时间后执行，适合 Search Suggestion：

```text
input events:  a--b--c------
execution:              x
```

必须处理取消旧 Timer、组件 Unmount 和旧请求响应。不要让 Debounce 造成输入本身延迟，Input State 应立即更新，只延迟副作用。

## Throttle

在固定时间窗口最多执行一次，适合 Scroll/Resize Progress。选择 Leading/Trailing 行为，并在清理时取消 Pending Callback。

## React Render 优化

顺序应是：

1. 用 Profiler 找到慢 Component。
2. 缩小 State 更新范围。
3. 拆分 Component 和 Context。
4. 稳定必要 Props。
5. 使用 `memo`、`useMemo`、`useCallback`。
6. Virtualize 或移除昂贵 DOM。

`memo` 进行浅比较；若每次都传新 Object/Function，可能没有收益。自定义深比较可能比重新 Render 更昂贵。

## Browser 优化

- 避免 Layout Thrashing：交替读写 Layout。
- Animation 优先 `transform` 和 `opacity`。
- 大计算放 Web Worker。
- Long Task 拆分并让出 Main Thread。
- 使用 `requestAnimationFrame` 协调视觉更新。

## 常见错误

- 未测量就给所有 Component 加 Memoization。
- Debounce 后未取消旧 Request。
- Virtual List 破坏 Tab 顺序和可访问性。
- 在 Render 中排序/过滤巨大数组且每次重复。
- 把所有状态放在页面 Root，导致整页更新。

## 总结

优化首先减少工作量，其次减少工作频率，最后才缓存工作结果。Profiler、合理 State Boundary 和 Browser Main Thread 知识比盲目 Memoization 更重要。
