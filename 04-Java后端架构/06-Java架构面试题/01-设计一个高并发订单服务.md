# 01. 设计一个高并发订单服务

## 需求

澄清 Peak QPS、商品数、库存一致性、支付流程、SLA、Region 与超卖容忍度。关键 Invariant：订单唯一、金额可追溯、库存不为负、支付不重复。

## 架构

```text
Client -> API Gateway -> Order Service -> PostgreSQL
                         |-> Inventory Service
                         |-> Payment Service
                         +-> Outbox -> Kafka -> Fulfillment/Notification
```

Order Service 无状态、Multi-AZ。创建使用 Idempotency Key。价格在服务端重新计算并保存 Snapshot。

## 数据与一致性

本地 Transaction 写 Order + Outbox。库存使用条件更新/Reservation，Payment 使用独立 Idempotency。Saga 管理 Reserve → Authorize → Confirm，失败时 Release/Refund。

## 高并发

- 商品读取 Cache。
- 热点库存按 Product Partition/Queue 或原子条件更新。
- 通知异步。
- 有界 Pool、Rate Limit、Backpressure。
- 数据库 Index、Partition/Archive 按证据演进。

## 故障

Payment Timeout 进入 PENDING 并查询状态；Event 重复由 Consumer 幂等；卡住 Saga 由 Reconciliation 修复。Recommendation 故障不阻断 Checkout。

## 观测

订单成功率/P99、库存冲突、Payment Pending、Outbox Lag、Saga Age 和 Cost/order。

## 面试亮点

明确 Transaction Boundary、Unknown Outcome、热点处理、Idempotency 与用户可见状态，而不是只说 Kafka + Redis。
