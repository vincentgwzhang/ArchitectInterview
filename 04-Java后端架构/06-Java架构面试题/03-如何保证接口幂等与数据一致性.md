# 03. 如何保证接口幂等与数据一致性

## 先定义语义

区分重复请求、并发更新、跨服务部分失败与消息重复。不同问题需要不同机制。

## 创建接口

Client 发送 Idempotency Key。Server 在同一 Transaction 中创建 Key Record 与业务数据，Unique Constraint 防竞争。保存 Request Fingerprint 和 Response。

## 更新接口

使用 Version/ETag + `If-Match` 实现 Optimistic Concurrency；数据库条件更新和受影响行数确认防 Lost Update。

## 跨服务

- 本地 ACID 保护单 Service 数据。
- Outbox 保证业务提交后 Event 可发布。
- Consumer 去重/自然幂等。
- Saga + Compensation 处理多步骤。
- Reconciliation 修复长期偏差。

## Timeout

Timeout 是 Unknown Outcome。Client 用原 Idempotency Key 重试或查询 Operation Status，不能生成新 Key 盲目再执行。

## 一致性选择

对余额、库存等 Invariant 使用强控制；对通知、Analytics 使用 Eventual Consistency。定义 Staleness 与收敛 SLO。

## Observability

监控 Duplicate、Conflict、Outbox Lag、Failed Compensation 和 Reconciliation Difference。

## 面试亮点

没有“Exactly once”魔法。端到端效果来自 At-least-once Delivery + Idempotent Processing + Constraint + 对账。
