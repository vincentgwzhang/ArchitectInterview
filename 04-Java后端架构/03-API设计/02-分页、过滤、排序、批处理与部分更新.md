# 02. 分页、过滤、排序、批处理与部分更新

## Pagination

Offset Pagination 简单，适合小数据和随机跳页，但深分页慢，且并发插入导致重复/遗漏。

Cursor/Keyset Pagination 使用稳定排序键：

```http
GET /orders?limit=50&after=eyJjcmVhdGVkQXQi...
```

排序必须唯一且稳定，如 `created_at DESC, id DESC`。Cursor 应不透明、签名或验证，不能让 Client 依赖内部结构。

## Filter 与 Sort

只允许白名单字段、Operator 和最大复杂度，防止任意 Query 造成慢 SQL 或数据探测。为常用组合设计 Index，并设置 Page Size 上限。

## Batch

Batch API 减少网络 Round Trip，但需定义：

- 最大 Item 数/总大小。
- All-or-nothing 或 Partial Success。
- 每项 Error 与 Idempotency。
- 异步 Job Threshold。

超大批量应返回 202 + Job ID，而不是保持长 Transaction。

## Partial Update

JSON Merge Patch 简单，但 `null` 可能表示删除；JSON Patch 能表达操作但更复杂。明确字段缺失、Null 和只读字段语义。

用 ETag/Version + `If-Match` 防止 Lost Update：版本不匹配返回 412 或 409。

## Response

返回 `items`、`nextCursor` 和必要 Metadata。昂贵的 `totalCount` 可选或异步计算，不要默认每页执行全表 Count。

## 总结

集合 API 的关键是稳定顺序、受控查询、并发更新和容量边界。Cursor、白名单和异步 Batch 能支持规模化。
