# 02. 索引、执行计划、锁、隔离级别与死锁

## Index

B-tree 适合等值、范围和排序。Composite Index 遵循最左前缀，其顺序应匹配常见 Filter/Sort。Covering Index 减少回表，但增加 Storage 与写放大。

不要为每个字段建 Index。每个 Index 都增加 Insert/Update、Vacuum 和迁移成本。

## Execution Plan

使用 `EXPLAIN ANALYZE` 观察实际行数、扫描方式、Join、Sort 和 I/O。估算与实际差距大可能来自统计信息过期、数据倾斜或相关性。

慢 Query 不一定缺 Index，也可能是返回过多、N+1、错误 Join、Lock Wait 或连接排队。

## Lock

行锁、表锁、意向锁和 MVCC 行为因数据库而异。Transaction 越长，持锁时间越长。禁止在 Transaction 内等待慢 HTTP 或用户输入。

## Isolation

常见级别：Read Committed、Repeatable Read、Serializable。更强 Isolation 降低异常但可能增加 Conflict/Retry。业务应明确防止 Lost Update、Write Skew 等哪种风险。

## Deadlock

数据库会选择 Victim 回滚。应用需要 Retry 整个 Idempotent Transaction。预防：统一访问顺序、短 Transaction、合适 Index、减少锁范围。

## 监控

Slow Query、Buffer Hit、Rows Scanned/Returned、Lock Wait、Deadlock、Connection Wait 和 Replication Lag。

## 总结

索引和隔离都是读写权衡。以 Execution Plan 和并发行为为证据，才能正确优化 Query 并保护一致性。
