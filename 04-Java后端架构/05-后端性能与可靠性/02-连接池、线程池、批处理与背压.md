# 02. 连接池、线程池、批处理与背压

## 有界资源

Thread、DB Connection、HTTP Connection、Queue 和 Memory 都必须有上限。无限 Queue 只会把拒绝变成超时和 OOM。

## Pool 对齐

假设 50 个 Pod，每个 DB Pool 30，总潜在连接 1,500。数据库若只安全支持 500，Auto Scaling 会放大故障。应联合设计 Pod Max、Pool Size、Proxy 和 Transaction Duration。

Thread Pool 大于 DB Pool 时，多余线程会等待连接；DB Pool 过大则增加数据库 Context 与 Lock 压力。

## 批处理

Batch 减少 Round Trip，提高吞吐：JDBC Batch、Kafka Batch、API Bulk。但 Batch 越大，Latency、Memory、失败重试范围和 Transaction 时间越大。

按 Size 或 Time Flush，并定义 Partial Failure 与 Idempotency。

## Backpressure

下游慢时，上游必须减速：

- Bounded Queue。
- Semaphore/Concurrency Limit。
- Reactive Demand。
- 429/503 + Retry-After。
- Queue Consumer 根据 Lag 扩容。
- Load Shedding。

Backpressure 若不能跨协议传播，就在边界设置 Buffer 与明确拒绝。

## Timeout Budget

上游 Deadline 应大于内部步骤总预算，下游 Timeout 小于剩余 Deadline。不要让每层各自等待 30 秒。

## 监控

Active/Max、Queue Depth/Age、Wait Time、Reject、Batch Size、Connection Acquire、Downstream Latency。

## 总结

稳定性来自资源有界和压力传播。Pool、Batch 与 Auto Scaling 必须按端到端容量共同设计。
