# 04. 幂等、去重、补偿与最终一致性

## 幂等

相同操作执行多次，业务结果等同一次。HTTP Method 名称不能自动保证业务幂等，必须设计 Key、Constraint 或状态检查。

```text
Idempotency Key -> Request Fingerprint -> Processing/Result
```

原子写入 Key 与业务结果，定义 Retention 和并发重复行为。

## 消息去重

Kafka/SQS 常见 At-least-once。Consumer 可使用：

- Processed Event Table + Local Transaction。
- Natural Business Key/Unique Constraint。
- Entity Version。
- 幂等 Upsert。

无限保存所有 Event ID 成本高，需要 Retention 或业务自然幂等。

## 补偿

Saga Compensation 是新的业务动作，不是数据库 Rollback。例如 Payment Refund、Release Inventory。补偿可能失败，必须可重试、可审计并支持人工处理。

## 最终一致性

定义：

- Source of Truth。
- 允许的 Staleness。
- 收敛机制。
- 冲突处理。
- Reconciliation。
- 用户可见中间状态。

“最终会一致”必须有 SLO，例如 99.9% Event 在 30 秒内处理。

## Unknown Outcome

网络超时后先 Query Status，不盲目再次扣款。状态机可以使用 PENDING/UNKNOWN，等待 Callback 或 Reconciliation。

## 总结

分布式系统要假设重复、乱序、部分失败和未知结果。幂等、状态机、补偿与对账共同保证业务收敛。
