# 05. 日志、指标、链路追踪与线上问题诊断

## 三类 Telemetry

- Metrics：趋势、SLO 和告警。
- Logs：离散事件与详细上下文。
- Traces：跨 Service 请求路径和时间。

通过 Trace ID、Business ID、Service Version、Region/AZ 关联。

## Structured Log

使用 JSON 与稳定 Event Name，记录 Error Code、Order ID 等可搜索字段。禁止输出 Token、Password、Card 和不必要 PII。异常在拥有处理上下文的边界记录一次，避免重复 Stack Trace。

## Metrics

RED：Rate、Error、Duration；资源使用 USE：Utilization、Saturation、Error。Label 不使用 User ID/Order ID 等高 Cardinality 值。

## Tracing

OpenTelemetry 传播 Context，Span 覆盖 HTTP、DB、Kafka 和关键 Domain Step。Sampling 应保留 Error/Slow Trace，并控制成本。

## 诊断流程

1. 确认用户影响和时间范围。
2. 检查 SLO/Golden Signal。
3. 按 Version/Region/Tenant 分段。
4. 用 Trace 找慢点/错误依赖。
5. 用 Log/DB/JFR 深入。
6. Mitigate、验证、再 Root Cause。

## 告警

Page 应对应用户影响并有 Runbook。CPU 高但无影响可作为 Diagnostic Signal；Error Budget 快速燃烧才是行动信号。

## 总结

Observability 不是数据堆积，而是从用户症状快速定位到组件和版本。统一语义、关联 ID 和可执行告警最重要。
