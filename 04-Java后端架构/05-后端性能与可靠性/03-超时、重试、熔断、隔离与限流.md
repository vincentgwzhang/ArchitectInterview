# 03. 超时、重试、熔断、隔离与限流

## Timeout

所有远程调用都应有连接与读取 Timeout，并遵守端到端 Deadline。Timeout 后操作可能已成功，写操作需 Idempotency/Status Query。

## Retry

只重试 Transient Error，使用 Exponential Backoff、Jitter、次数上限和 Retry Budget。多层 Retry 会乘法放大，明确由哪一层负责。

## Circuit Breaker

错误或慢调用超过阈值后 Open，快速失败；Half-open 用少量请求探测恢复。按 Dependency/Operation 隔离，阈值基于真实 SLO，避免一个 Endpoint 拖累全部。

## Bulkhead

为不同 Dependency/Tenant/Workload 使用独立 Pool、Semaphore 或 Queue，防止资源耗尽传播。关键交易与 Batch 不共享无限资源。

## Rate Limit

Token Bucket 支持 Burst，Leaky Bucket 平滑流量，Fixed/Sliding Window 简单但语义不同。按 User/Tenant/API/Cost 限制并返回 429 + Retry-After。

## Fallback

只在业务允许时返回 Cache/Stale/Default。Recommendation 可降级，Payment 不能伪造成功。降级必须可观测并定期测试。

## 避免 Resilience Storm

Retry、Hedging、Fallback 都会增加额外请求。使用 Deadline、Budget、Concurrency Limit 和 Load Shedding 控制。

## 总结

Resilience Pattern 的目标是限制故障影响，不是隐藏所有错误。明确业务语义、资源边界与监控才能安全使用。
